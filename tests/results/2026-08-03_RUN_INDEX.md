## Reproducing

```bash
# corrected mocap-scale single run
airstack test -m autonomy --sim isaacsim --num-robots 1 --stress-iterations 1 \
  --trajectory-types Circle --trajectory-scale 0.15 \
  --trajectory-altitude 3.0 --trajectory-velocity 0.5 -v

# 10-iteration repeatability
airstack test -m autonomy --sim isaacsim --num-robots 1 --stress-iterations 10 \
  --trajectory-types Circle --trajectory-scale 0.15 \
  --trajectory-altitude 3.0 --trajectory-velocity 0.5 -v
```

## Caveats for whoever picks this up

- **Altitude must be >=3.0 m.** `takeoff_landing_planner` completes on an absolute
  `takeoff_acceptance_distance: 0.3` m band, while `test_takeoff` asserts 10% of
  target. Those only agree at >=3.0 m, so a 1.5 m target fails regardless of how
  well the drone flies.
- **After takeoff the stack holds vertical velocity, not altitude.** Success
  switches the trajectory controller to `ROBOT_POSE`, which overwrites the tracking
  point with current measured odometry, zeroing position error by construction.
  Measured hover deficit was -0.39 m at a 1.5 m target and -0.37 m at 2.5 m —
  constant, not proportional.
- The docs baselines in `docs/development/intermediate/testing/end_to_end_testing.md`
  (~0.98 m mean, ~1.55 m RMSE) are pre-fix and no longer valid.
- These runs used the local `alpha.5` images because `.env` pins `0.19.0-alpha.7`,
  which is not present locally and needs registry auth to pull. The Docker build
  inputs are identical between those two versions (only Jetson files differ).
