## Common project-defined metrics

Canonical output: exact supplied source time_ns list(Python integer nanoseconds), parallel nullable4x4 T_world_from_commonRGBrectifiedCamera in metres, nonnegative contiguous segment IDs, terminal status and runtime log. Camera/body/NED conversion is source-defined and frozen in the adapter. No timestamp search, offset fit, duplicated time, source reordering or estimator-filled missing pose. A null pose retains a missing output. Same-named segment may not resume after a hole; resets create new contiguous IDs. Reference-invalid frames remain in source/pose-coverage denominators and are excluded explicitly from accuracy targets. Pose rigidity uses existing MS² serialization rule: Frobenius orthogonality and determinant error<=1e-5, proper-SO3 polar roundoff handling only; no repair of gross invalid rotations.

Report translation ATE RMSE with SE3 rigid alignment(no scale), plus origin-aligned ATE, per contiguous segment and as frame-weighted aggregate. SE3 alignment with position rank<2 is explicitly unidentifiable; return null rather than a misleading fitted number. Origin alignment stays available. Evaluation alignment is post-prediction only. Report segment/reset counts so independent segment alignment cannot hide failures.

Primary local metric: overlapping source-time RPE at1second, endpoint the first source timestamp>=t0+1s and <=t0+1.15s. Require every intervening source/reference pose valid, consecutive source gaps<=150ms, and all estimated poses present in one contiguous segment. Residual inv(reference_delta)@estimate_delta; translation metres and principal rotation degrees, no reference transport into predictions. Report actual interval durations and full expected versus scored pair counts. This is project-defined timestamp handling, not an official MS² metric. [evo's metric documentation](https://github.com/MichaelGrupp/evo/wiki/Metrics) explains the distinction between SE3, Sim3, absolute and relative pose evaluation; our exact pairing/coverage contract is stated here.

Report acquisition/output pose coverage, reference validity/exclusions, RPE coverage, longest contiguous segment, resets, failure counts, terminal status, runtime/GPU memory, inference calls and output latency separately. An engineering success flag requires terminal success, no reset, >=95% pose coverage and >=95% reference-qualified RPE coverage; this is a declared project threshold, not a published dataset standard. Accuracy on available fragments remains descriptive. Never rank short failed fragments as complete-recording winners. Aggregate by equal recording weight, then report seeds/conditions separately; pooled interval means are secondary. No confidence claim from correlated intervals or only two reserve records.
