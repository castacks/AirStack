# Proposed AirStack integration architecture

Use the native USD/RTX path for scene state, geometry, masks, depth and an RGB product. Independently derive visible spectral and LWIR radiance from the same *stamped* camera rays and first-hit surfaces in an external sidecar. Material bindings carry temperature K, emissivity profile, irradiance and reflected environment. The environmental sidecar owns seeded periodic latent state, metre-based path lengths and spectral coefficients. Separate the renderer RGB and model RGB outputs by explicit provenance fields.

At simulation tick (t), latch USD transforms, (K), near/far clipping, resolution, background and environmental snapshot. Pair both sensors with integer nanosecond acquisition stamps and frame IDs. Map USD camera axes into ROS optical axes (right, down, forward), declare stage metres per unit and world up axis, and validate optical-to-body static transforms. Axial depth times (\sqrt{1+x_n^2+y_n^2}) is ray range. Choose one simulated clock authority and handle resets as new run IDs. Track exposure time separately from publication time and wall time. Reject stale or ambiguous association explicitly.

ROS 2 Jazzy transport would publish namespaced `sensor_msgs/Image` and `CameraInfo`, appropriate `tf_static`/TF, and `rosgraph_msgs/Clock`. Declare encoding (RGB8 for renderer output and a specified raw code encoding for LWIR), QoS, timestamps and calibration ID. Preserve raw modeled radiance and validity/rail masks in sidecars. Scoring-only target IDs and labels belong in an offline stream with a separate access path. AirStack's stack topology would consume sensor outputs through declared robot namespaces. A future geometry-only pilot candidate is the WP03 pinhole scene with 33×25 pixel centres, two opaque planes and three moving-blocker poses. Require exact non-boundary first-hit IDs, projected control points within 0.1 px, matched ray ranges within 1 mm, camera/model stamp equality and explicit edge discrepancies. Capture clear and occluded controls twice with one pinned stage, image digest, renderer preset, SDG seed, fixed time step and asset checksums. Compare discrete geometry exactly off edges and retain measured RGB/depth replay deltas. Predeclare draw count and tolerances if stochastic replay is used. Record p50/p95/p99, wall FPS, peak RAM/VRAM, dropped/duplicate/misaligned frame counts and writer bandwidth before assessing real-time feasibility. These pilot criteria are design proposals pending approval.
