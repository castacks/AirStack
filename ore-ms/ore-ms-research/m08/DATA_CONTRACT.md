# Forecast inputs and leakage controls

The deployable CLI accepts exactly `case,realization,split,R_code,G_code,B_code,lwir_code` from an issue-time feature CSV. It accepts frozen physical and nuisance metadata and uses M07's accepted public likelihood. A case label selects the predeclared set of allowed channels and external constraints. It does not reveal future state or mistaken actual parameter choices. The forecast code uses realization/split only as output keys. Forecasts for equal admissible measurements must be identical.

Evaluation labels store future burden and transmission by case, realization and horizon. They are opened by scoring after prediction. The oracle file contains issue-time latent coefficients only, and its separate command produces a separate output. It is never loaded by the deployable command. Dataset generation uses fixed private truth streams and permitted controlled case interventions. Ninety-six or more future labels from a trajectory do not make independent realizations; the split and scoring unit are the whole realization. This experiment uses 64 development and 128 holdout realizations, with paired scenario interventions. Neither split is used to fit model dynamics or tune thresholds.

Unknown range, material, external domain, or dynamics can invalidate a forecast for the defined target path. Clipped, missing, weak or occluded issue observations may fall back to a labeled prior on that known reference path. Unknown thermal emission removes the LWIR channel, preserving eligible RGB. This is a predicted atmosphere along a stated path, with no claim of future geometric visibility or future image codes.
