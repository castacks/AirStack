## Witness comparison

| Candidate | Underlying event and independence | Bracketing suitability and decision |
| --- | --- | --- |
| Existing `World.current_time_step_index` | Legacy native PhysX step deliveries counted by `SimulationContext`. Independent of the ROS graph. Nonzero at the start, unchanged across this render. | Keep as a comparison and retain the current gate. It witnesses delivered events. STOP resets it. |
| Direct `omni.physx.get_physx_interface().subscribe_physics_on_step_events(fn, pre_step=False, order=0)` | The packaged binding specifies a callback after each physics step. Separate subscription, no graph and no Simulation Manager view wrapper. Native delivery on this render path is unresolved. | Best candidate for later qualification. Retain the subscription handle outside on-update callbacks, log positive finite step deltas, and sample the event count before render, after render and after subscriber drain. Setup, reset and startup events must be distinguishable from events in the bracket. Unavailable, absent or contradictory event evidence keeps the gate closed. |
| `SimulationManager.register_callback(..., POST_PHYSICS_STEP)` | Wraps that native post-step subscription and suppresses delivery before the simulation view is created. Independent of graph output. | Useful cross-check after view readiness is recorded. The additional early-event filter makes it a weaker lead for this investigation. |
| `SimulationManager.get_num_physics_steps()` | Native manager step-count accessor exposed as a separate method. The tagged C++ interface declares its meaning and packaged tests exercise normal play, pause and stop. Internals and behavior on this exact render path are unverified. | Easy to sample at all three boundaries alongside the raw event evidence. The bundled test skips external time-manager configurations due to differing physics-step accounting. Do not substitute this count on its own. |
| Kit current time or timeline ticks | Playhead state. Can move through manual timeline commits and can remain stationary during capture. Independent readout from the ROS graph. | Suitable for context. Proves playhead progression when it changes. Does not prove physics advancement. |
| Native manager time, graph compute counters, render reference and ROS callbacks | The manager monotonic value is the clock graph's source. Graph evaluates playback; render reference identifies a captured frame; callbacks witness transport. | Preserve as timing, frame and transport evidence. None gives independent proof of a completed physics step. |

A separate on-demand `OnPhysicsStep` graph ultimately uses the native post-step subscription too and adds graph setup and PLAY-event dependencies. The direct subscription would add less instrumentation. Before an epoch gate change, any later isolated check should record a no-advance control and a separate explicit stepping positive control, then bracket the exact Replicator call and compare the post-step stream with both counters. A render that still shows no new physics event remains unqualified. If the isolated route cannot produce a witnessed physics boundary, changing the stepping protocol requires a new controlled qualification.
