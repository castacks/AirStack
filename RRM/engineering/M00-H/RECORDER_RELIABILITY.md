# Recorder reliability contract and measured scope

Local offline synthetic-file engineering only; no runtime recorder qualification or REC-01 closure. Schema2 declares run/segment/config identity, source/boot/PID/clock/producer sequence, producer and receipt monotonic/wall clocks, event/payload, global sequence and chained SHA256. Max serialized record65536 bytes is a local buffer bound, not a qualification threshold. One record is buffered at a time; producer adapters do not create asynchronous queues. Concurrent writers are unsupported; O_EXCL creation and one writer per segment are required.

Each record is fully written using an explicit partial-write loop, then fsync acknowledged before sequence/hash state advances. Interrupted writes retry up to8 interruptions; zero/invalid progress and overflow fail closed. Interrupted fsync or disk failure is not acknowledged/retried into an invented durable state. Initial directory fsync records the new name on the tested filesystem; storage/hardware power-loss guarantees are unknown. No general stream flush is used: binary os.write has no user-space file buffering; fsync is the synchronization boundary.

Constructor init/ready, close terminal and health_report distinguish acknowledgment and local failure. Failed writes/sync/schema/source/sequence/clock cause a degraded latch and descriptor closure, with no silent resume. If the device cannot write, the recorder cannot reliably log its own failure. An independent supervisor must retain health_report/process-exit and missing terminal outside this failure domain. A visible complete terminal after failed fsync is only structural evidence, not proof of acknowledged durability; scanner explicitly reports durability_verified=false. No host/process/GPU failure survival is inferred from hashes.

scan_bytes validates strict schema/version/identities, hash chain, complete newline records, global/producer sequence continuity, per-source monotonic and receipt clock order, configuration and init/ready/terminal/health. Wall-clock steps are retained separately. It stops at corruption/gap/truncation and reports a verified prefix; it never sorts away errors or repairs the original. Missing expected events remain explicit. No signature/authenticated clock is implied by checksums. Out-of-order observations are rejected or retained as semantic warnings rather than given fabricated timestamps.

Restart reads the old segment without writing it and creates a distinct segment containing original raw digest, verified-prefix count, errors and data_loss_possible. Old interruption/loss keeps the recovery result DEGRADED; new healthy writes cannot erase the earlier loss. Restart is journal-file creation only, never a simulator/guard restart. Recovery does not reset any guard latch. Original output may be empty or partial; missing terminal is always visible.

Tests inject partial/zero writes, InterruptedError, disk/initialization/shutdown-sync errors, malformed/duplicate/missing/out-of-order/corrupt events, invalid identity/config, nonmonotonic clocks and record-size overflow. Real temporary files under RRM test local sync and immutable linked recovery. One offline Python child exits23 without close, demonstrating detection of a local missing terminal after abrupt process exit, not simulator or independent-recorder failure survival. Native collection transport, external supervisor, security, clock calibration, overhead, finite storage/rotation, process/host common failures and physical durability remain NOT VERIFIED.
