# Independent diagnostic recorder v1

`recorder.py` implements an observational append writer and offline auditor. Its only sink interface is write/flush on an injected file-like object. It has no ROS, vehicle, simulator, subprocess, socket, startup, parameter or guard-state API. CLI deliberately exits BLOCKED; no live collection service was started. Runtime event adapters and independent supervision remain unresolved rather than simulated as real data.

`EVENT_SCHEMA.json` defines stable records: schema version, run/configuration identity, global sequence/event ID, kind, source/boot/PID/producer sequence and clock ID, producer monotonic and wall nanoseconds, recorder receipt monotonic and wall nanoseconds, evidence class B, payload and SHA256 chain. Input provenance is caller-declared; no source authentication or clock calibration is implied. Wall-clock steps are retained; per-producer-clock monotonic regression and recorder receipt regression are errors. Never subtract unrelated clock origins. No simulation time substitutes for guard steady time.

Constructor emits recorder_init then recorder_ready only after complete writes/flushes. This establishes offline writer readiness, not disk durability or external supervisor independence. Every startup/deadline/MAVROS/app/graph/recovery event is supplied by a future adapter; generic events may repeat with new producer sequences, but duplicate record IDs/sequences are errors. `close()` emits exactly one terminal event; post-terminal or failed-writer resume is rejected. Short write, flush error or write failure raises RecorderError and latches local failure. Data-loss/failure events also latch failure; a failed writer cannot promise to record its own failure or terminal event. Independent supervisor must record missing process exit/stream termination and retain partial bytes outside the failed writer's domain.

Auditor verifies schema fields, hash chain, run/configuration identity, producer/receipt monotonic sequences, init/ready/terminal, health/loss, expected missing events and documentary recovery ordering. It never sorts away gaps. Graph-before-app in the declared sequence is flagged for review; receipt order alone is not calibrated causal timing. Guard reinitialization after deadline for the same guard instance is rejected. Recovery documentary order is request→sealed→isolated→approved; approval records in a supplied stream are untrusted evidence, not authority or instructions to this library.

Tests use synthetic clocks and in-memory/failing sinks, plus saved synthetic fixtures. No runtime latency, recorder-survival or REC-01 qualification evidence is fabricated. Bounded queueing/spool rotation, producer authentication, crash/fsync durability, dropped-event detection when no producer gap is available, independent collector/process/host loss, clock maps and finite storage/resource limits remain unresolved. Compose gives recorder no network and a read-only spool view; upstream components currently emit no standardized spool transport. A general shared host/volume can still fail together; runtime isolation gate remains NOT PASSED.
