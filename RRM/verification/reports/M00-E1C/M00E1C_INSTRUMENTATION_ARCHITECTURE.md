# Startup instrumentation architecture

**DESIGN PROPOSAL ONLY — NO DEPLOYMENT OR TIER B EXECUTION AUTHORIZED**

EV01–EV11 in M00E1C_EVENT_CATALOG.csv define each event, source/collection method, timestamp domain/map, output and limitation; they cover I01–I06 and every HD01–HD08 hypothesis. No hooks, sampler, recorder, trace session or simulator is installed or started. Existing M00-C/D/E1B records are dated evidence, not fresh runtime observations.

Proposed pipeline: native producer emits bounded async event record → private per-attempt append spool → independent outside-executor collector/supervisor → immutable raw/normalized records, event coverage/gap report, process status and SHA-256 manifest → out-of-band archive digest/receipt. Keep raw bytes, parse-tool release, source/installed binary/config/scene/cache IDs and transformation provenance. Capture must start and prove health before any allowed software startup. Collector reads data only and cannot dispatch commands into the experiment; control-plane stop ownership is separate. Buffer overflow/backpressure/disk/serialization failures emit explicit dropped/late/error events and abort according to approved operational bounds, never silently produce PASS. Native control callbacks must not block on synchronous disk/network writes; actual overhead/loss behavior needs later approved measurement.

Event contract extends the existing M00-D format: schema revision, authorization/configuration/trial/attempt/pair IDs, workflow/host/boot/process-instance/PID identity, instrument/event name, parent-event ID, monotonically increasing source sequence, native integer timestamp and unit/clock domain, source versus receipt, calibration/map ID with uncertainty, actual value/type/reason and dropped/missing/late/error fields. Boolean is not an integer timestamp. Constructor event must identify the original member-initialization origin without moving it; no numeric origin can be reconstructed from the old deadline log. Separate new process/boot/simulation epoch identities after reset/restart; no unrecorded continuity assumption. Schema-valid input is not proof of authentic/completely acquired events.

Clock discipline: guard and producer steady ns for local elapsed spans; kernel boot ticks with rate and boot ID for lifecycle; raw producer realtime and log/Docker receipt UTC as separate domains; PX4 boot clocks and simulator time with epochs retained natively. Record monotonic–realtime bracket samples before/after acquisition and discontinuities, owner time-sync status, mapping offset/drift and measured uncertainty. Cross-domain subtraction requires reviewed map evidence and uncertainty; otherwise UNMEASURABLE. Timestamp overlap and printed nanoseconds do not establish synchronization or accuracy. Simulation pause/time reset cannot extend a wall-time acquisition bound or be substituted for startup wall time.

Resource sampling initially proposed at1Hz, with event transitions recorded on occurrence; rates, maximum duration/bytes/storage reserve, queue sizes, packet filters and overhead budget remain owner/reviewer/PD decisions, not F00 acceptance limits. Freeze actual cadence and collector/producer budget before any active scope. No resource-stress variation is introduced. Fault/exit/stop behavior of independent supervision must be separately demonstrated on approved inert fixtures, then actual exact rig as authorized; design review does not close REC-01.

Preserve historical observations from one episode: **19.276162179 seconds** deadline error→MAVROS connection and **74.228771713 seconds** application complete→vehicle graph. Neither is a controlled acceptance threshold. The first is not total PX4 startup/wire latency; the second is not exclusive scene-load time. Twelve M00-D characterized intervals and seven missing quantities remain unchanged. E1C can replay these raw records offline; repeated parsing/reconnections/readiness samples do not add startups or estimate variability.

Future independent-trial convention preserves original24-row2policies×2cacheconditions×6repetitions and fixed order/first-pair checkpoint. Any diagnostic-host substitution requires explicit candidate/claim-limit review before binding that schedule. Allocate exclusive attempt directory by authority/config/trial/attempt, distinct process/boot/scene identities and actual execution UTC/native clocks. Record all starts including setup/failed/aborted/incomplete, no replacement success or hidden cache warm-up. Use identical source/guard/build/assets/limits/observer overhead and independent cloned cache bytes within pairs, with pinned pre-existing audited warm artifact for warm condition. Cache absence or unsupported scene seed returns for amendment before any start.

Analyze all raw phase durations, missing/censored events, per-cell attempted/completed/failed/aborted/incomplete counts, observed medians/ranges and paired P1−P0 contrasts with order/cache/resource/overhead covariates. Six repeats/cell are exploratory, not powered reliability/p95/confidence qualification. Nested phase intervals are not independent samples. Resource/discovery correlation alone is not causal attribution; HD06 timing fit and HD07 defect decisions also require authoritative requirements/state semantics. No new requirement threshold is adopted, and E4 readiness≥30s entry remains distinct from historical10.0s guard configuration.
