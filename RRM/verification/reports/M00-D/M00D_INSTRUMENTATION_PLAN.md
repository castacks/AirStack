# M00-D instrumentation plan

Implemented tools are **offline only**. `RRM/scripts/m00d_characterize.py` reads immutable M00-C JSON, independently computes named intervals using Decimal native timestamps, rejects clock/episode/boot mismatches, and checks the dependency graph. It has no Docker, ROS, networking, subprocess or service-control API. Generated outputs are exclusive-create to fixed M00-D paths; `--check` only compares existing outputs. There is no launch/restart/arm/actuator path.

`RRM/scripts/m00d_validate_events.py` validates the proposed event record format/order from a local JSONL input. It never attaches to a process or changes a runtime. It explicitly returns coverage_qualified=false and requirement_verdict=NOT_ASSESSED, even for a format-valid trace. A valid schema does not prove missing events were acquired, the source is authentic or the state machine passed.

[Instrumentation catalog](../../../evidence/M00-D/instrumentation-catalog.csv) defines I01–I06 workflow, scene, child process, communication/callback, guard and resource events, clocks, discrimination purpose and approval status. These **future** hooks/adapters are not deployed; no protected code is patched. Without them, scene-exclusive latency, guard numeric origin/callback history, discovery latency and resource attribution remain missing.

Proposed record contract `M00D-INSTRUMENTATION-PROPOSAL-v1`: schema, episode_id, producer_id, process_instance_id, boot_id, instrumentation_id, event, sequence, clock_domain, unit and integer native_time. Supported pairs are STEADY/ns, REALTIME/ns, SIMULATION/ns and KERNEL_BOOT/ticks with positive ticks_per_second. Boolean values are not integer timestamps. Per-producer/process/episode/boot/clock sequence must strictly increase; times must not go backwards. Reset/discontinuous domains need new identity and declared clock-map evidence; timestamp overlap is insufficient to establish mapping. Fields describing uncertainty, source event, receipt, provenance, parent event and dropped/late evidence should accompany approved future traces. No fabricated current startup record or clock map is emitted.

Future native logs/clock/asset/network captures must keep native timestamps and register exact transformation bounds before computing cross-domain elapsed time. Producer UTC logs and Docker receipt UTC stay distinct domains; shared printed units do not make them acquisition-synchronized. Preserve original bytes, process/episode/reset markers, source and installed binary identities, environment conditions, sample cadence/overhead, missing channels and failed attempts. Acquisition completeness, ordered recording and OS exit status remain independent evidence requirements (REC-01 not satisfied by these tools).

Hooks must use bounded asynchronous buffers, explicit drops/errors and process-scoped identities; no synchronous control-callback storage. Review overhead against the authoritative budget before deployment. No default numerical sampling/overhead threshold is promoted to F00 acceptance. Adding source hooks, starting an isolated logger, or attaching synthetic ROS/mock startup services requires a separate reviewed task and, for Tier B/protected changes, written PD authority.

M00-D executes only Tier A offline analysis and read-only Docker metadata inspection. No synthetic live ROS publications, service requests, parameter writes, launch or restarts occurred. Unit cases mutate in-memory copies of historical/synthetic records only. See `diagnostic-tests.txt` for 17 cases, including missing events, mixed clocks, boot changes, wrong units, graph cycles, invalid identities and no-false-qualification behaviour.
