# M00-E1 proposed Tier B execution procedure

PREPARED — NOT AUTHORIZED FOR EXECUTION

This is a review procedure, not an executable launcher. No service command is approved by this document. M00-E1 ends at local commit and handoff. M00-E2 cannot begin on package completion alone. Read the configuration register, operation register, instrumentation and safety reviews with the pending decision. OP01–OP07 each require separate written PD scope; no command manifest, target or hook candidate is yet approved.

1. **Resolve and freeze before execution.** Obtain technical review, exact target workflow/host/container identities, immutable image/source/installed binary/scene/parameter/network/resource manifests and reviewed overlay/launcher/instrumentation. Review the effective launch argv/env and preexisting entrypoint/autostart behavior. Supply actual allowlisted commands, operator, safety owner, external evidence root, clock strategy, finite stop/capture/storage bounds and cache artifacts. CHK01–CHK18 must have evidence and applicable approval, including safety attestation. Document-only checks do not satisfy runtime controls. If preparing these requires starts, obtain separate preparation authority before those starts. Record any consumed setup start; no hidden commissioning runs.
2. **Obtain PD decision.** A written decision must name the exact candidate manifest, target workflow, operations OP01–OP07, 24-start maximum, frozen matrix, reviewed controls/limits, operators, evidence root and expiry; it must expressly authorize M00-E2. Reject/defer means no execution. Changed candidate, safety condition, matrix or scope returns for review. No E1 signature or software output grants authority.
3. **Freeze the schedule.** Preserve M00-D: 24 proposed startups = 2 policies × 2 cache conditions × 6 repetitions per cell. `m00e1_plan.py --check` verifies the seeded schedule (20261127), shuffled 12 cache/repetition blocks and randomized P0/P1 order within each matched pair. Record pair/time/order covariates; do not reorder after observing outcomes. P0 starts interface concurrently with simulator as baseline. P1 defers guard construction until an independently observed, fresh dependency predicate is satisfied while preserving budget/freshness/type/readback/latch semantics. The exact finite wait/abort and predicate (PX4/transport/MAVROS connected safe state with source age, disarmed/non-offboard state and services) require reviewed implementation; avoid a circular dependency on the deferred guard. No timeout extension, synthetic state, latch clear or manual parameter repair.
4. **Prepare each assigned attempt without extra starts.** Use the approved exact target only. For fresh condition clone a dedicated clean cache; for warm condition clone the same pinned, pre-existing audited warm artifact for each matched pair member. Record cache manifest, compatibility and provenance. Do not create warm caches with undocumented simulator runs; if artifact unavailable, stop for an amended authorized plan. Never erase shared caches. Hold scene/assets, pair seed, source/config/limits and instrumentation constant across a pair; record host/GPU/ambient load. If the simulator does not support the proposed scene seed, declare the deterministic scene control and amend the matrix before authority. Readiness of cache and scene is currently unverified.
5. **Open evidence and start only after all controls pass.** Allocate the exact trial/attempt path, authorization/operator references and UTC/native-clock markers; start the approved independent recorder before any OP04/OP05 process start. Record workflow and process ownership. Execute the frozen allowlisted command manifest according to the assigned policy, without ad hoc launch flags. Observe all I01–I06 channels continuously. Any initiation of a simulator/PX4 startup, including partial/failed/setup, consumes an allowed attempt and is recorded; do not hide starts before recorder availability. If setup consumes the 24-start cap, fewer matrix cells complete; report that limitation instead of replacing attempts.
6. **Observe, classify, abort when required.** Apply the safety review's immediate abort rules and approved finite diagnostic window. Classify COMPLETED_DIAGNOSTIC, FAILED_STARTUP, ABORTED_SAFETY, ABORTED_EVIDENCE or INCOMPLETE_INTERRUPTION with reasons and missing channels; none means requirement PASS. Deadline expiry is recorded as a diagnostic event with latch history, never auto-repaired. Retain every attempt and its place in the original schedule. Stop only the target-owned processes through OP06; no automatic retry, no replacement and no substitute success.
7. **Seal and recover.** Retain exact source/images/installed binaries/config/environment/cache manifests; approved reproduction command manifest and actual argv/order; UTC execution start/end and native event records/clock mappings; raw stdout/stderr/PX4/MAVROS/DDS/guard logs; ordered event extraction plus tool revision and missing events; resource/network observations with actual cadence, gaps and overhead; process/recorder exit statuses; trial outcome/anomalies/abort/recovery/operator/authorization. Create SHA-256 manifest over every retained byte and separately record manifest hash; preserve partial hashes and explain unavailable files. Independent recorder health and durable archive receipt are separate checks; hashing alone is not REC-01 closure. Quarantine interrupted state and re-attest safety before the next scheduled start; extra startup requires amended PD scope.
8. **Analyze without qualification claims.** Show every attempted trial and missing/censored phase; never drop failed startups or substitute a later success. Report per-cell n attempted/complete/failed/aborted/incomplete, all raw phase durations, medians and observed ranges; retain pairwise P1−P0 phase and deadline-origin differences within cache blocks plus sequence/host/resource covariates. A six-pair-per-cache design supports initial mechanism contrasts and visibility of repeatability, not a powered test, population p95, reliability or qualification claim. Do not treat correlated nested phase intervals as independent samples. Optional descriptive paired uncertainty must name method/assumptions and show all six differences; with missing pairs report incompleteness, not imputation. Diagnose simulator subphases (HD01), spawn/firmware (HD02), order (HD03), transport (HD04), MAVROS/DDS (HD05), budget fit (HD06 requires authoritative requirement), latch semantics (HD07 requires requirement), and phase-correlated contention (HD08, causal resource intervention deferred). Do not claim causal resource/discovery attribution from correlation alone. Any further targeted interventions require a new reviewed plan.

Evidence convention (external root and AUTH_ID pending):
`<APPROVED_EXTERNAL_EVIDENCE_ROOT>/M00E2/<AUTH_ID>/CFG-M00E2-STARTUP-01/M00E2-TB-001/ATTEMPT-001/`.
Each frozen matrix row has a unique trial ID and path. Keep `trial-manifest.json`, `authorization/`, `configuration/`, `raw/`, `events/`, `resources/`, `outcome.json`, `reproduction/`, `SHA256SUMS` and detached manifest digest; setup/interruptions use explicit unscheduled IDs with authorization reference and consume the cap. Attempt directories are exclusive-create, never overwritten; a proposed later attempt remains unexecuted unless separately authorized and cannot replace the original result. Target commands and external-root assignment are intentionally unresolved evidence requirements, so the procedure cannot currently be executed reproducibly.

No numerical acceptance threshold is adopted here. Historical 19.276162179s and 74.228771713s remain n=1 observations. Existing 10.0s guard configuration is held constant only as the comparison baseline; authoritative startup allocation is missing. F00 E4 readiness≥30s entry is a separate source condition, not redefined as a startup timeout.
