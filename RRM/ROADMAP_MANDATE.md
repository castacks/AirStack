## Mandatory execution and handoff control

For every milestone: read roadmap/status; verify repository/ore_proj/HEAD/status and authorization; identify package/gate; capture protected/input/source identities; execute only scope; produce linked technical evidence; update original blocker/milestone dispositions and PROJECT_STATUS; check roadmap/status agreement; run applicable validation/integrity checks; inspect explicit RRM-only staged paths; locally commit deliverables and status together; report full commit SHA/results/limits to reviewer/PD; stop at required gate.

All new tracked artifacts remain under RRM. RRM-transfer, existing AirStack source/configuration/launch files, unrelated changes/history, supplied controlled input and sealed prior milestone evidence are protected. Read-only investigation does not authorize a restart, parameter write, goal, flight or integration edit. Document a concrete outside-RRM proposal and obtain PD approval before implementation. Preserve unrelated index/worktree changes and never reset/clean them. Use explicit staging, cached-path review and `git diff --cached --check`. No branch creation, indiscriminate staging, push, remote ref update, amend/reset/rebase or history rewrite without specific authorization. Large raw data/images/weights/caches remain outside Git with path/URI, byte count and SHA256 recorded in approved manifests.

Status commit identity convention: PROJECT_STATUS records the last full SHA **known at snapshot preparation** and names the completion commit as the commit containing that file, resolved by Git and an ignored local receipt after creation. A committed file cannot contain its own complete commit hash without circular self-reference. Never fabricate a current hash, amend sealed history or omit the final actual SHA from handoff. Routine future status updates refresh the known full SHA and as-of label before committing the new milestone. Final commit is reported to the user and independently inspectable with `git log -1 -- RRM/PROJECT_STATUS.md`.
